1. 본 문서를 제출하는 이유

카카오 심사 답변 인용:
“해당 서비스는 (회원가입 후 이용 가능한) 서비스로 원활한 심사 진행이 어렵습니다. 정확히 어떤 서비스인지 확인할 수 있도록 이용 동선을 포함한 사이트 화면을 첨부해 주세요.”

디그팟은 가족·연인·친구 등 친밀한 소그룹이 일기와 일정을 비공개로 공유하는 모바일 앱이기 때문에, 구조상 비회원 둘러보기(public landing)가 존재하지 않습니다. 일기와 일정은 그룹 멤버에게만 노출되는 사적인 정보이므로, 카카오·네이버·애플 소셜 로그인 후 그룹을 생성·참여해야만 본 화면들이 표시됩니다.

이 문서는 카카오 심사 담당자가 앱을 직접 설치·가입하지 않고도 전체 이용 동선과 카카오 로컬 API 가 호출되는 정확한 지점을 한 번에 확인할 수 있도록, 각 단계 화면을 와이어프레임/실 캡처로 정리한 보충 자료입니다.

필요 시 카카오 심사 담당자께 테스트 계정 + 초대 코드를 메일로 즉시 발급해 드릴 수 있으며, iOS TestFlight 또는 Android APK 빌드 전달도 가능합니다. (메일: chltmdgh517@naver.com)

3. 카카오 로컬 API 가 왜 필요한가

3-1. 사용 위치 — 그림일기 작성 화면 단 한 곳

그림일기는 날짜·사진·기분·날씨·장소·본문의 6개 메타 필드로 구성됩니다. 이 중 “장소”는 사용자가 그날 다녀온 카페·식당·관광지·공원 등의 이름을 일기에 함께 기록하기 위한 필드입니다.

사용자가 장소 이름을 직접 키보드로 입력하게 하면 오타·표기 불일치(예: “스타벅스 성수점” vs “스타벅스 성수1호점”) 가 발생해 일기 데이터의 정합성과 회상 편의가 크게 떨어집니다. 그래서 우리는 카카오 로컬 키워드 검색 API 를 이 한 지점에서만 호출하여, 사용자가 키워드를 검색해 정식 상호명을 선택하도록 합니다.

호출 API: GET https://dapi.kakao.com/v2/local/search/keyword.json
인증: Authorization: KakaoAK <REST_API_KEY>

3-2. 카카오 로컬 API 를 선택한 이유

  • 국내 장소 데이터 품질 — 한국 사용자의 일기에 등장할 카페·식당·골목 가게는 카카오 로컬이 가장 정확하고 풍부합니다.
  • 한글 키워드 매칭 — “성수동 카페”, “이태원 와인바” 같은 한글 자연어 검색이 자연스럽게 작동합니다.
  • 가벼운 REST 통신 — 카카오맵 SDK 임베드 없이 단일 GET 요청만으로 일기 작성 흐름에 매끄럽게 끼워 넣을 수 있습니다.
  • 심사 단계 카카오 로컬 도입 사례 다수 — 일기/메모 앱이 장소 메타데이터로 카카오 로컬을 활용하는 표준적 패턴입니다.

3-3. 데이터 보호 — 카카오로 보내는 것 / 우리 서버에 저장하는 것

데이터카카오로 전송자체 서버 저장
사용자 ID / 프로필❌ 전송 안 함✅ (소셜 로그인 토큰 + 닉네임)
일기 본문 · 사진❌ 전송 안 함✅ (그룹 멤버만 열람)
검색 키워드 (예: “성수동 카페”)✅ 사용자가 검색 버튼 눌렀을 때만❌ 저장 안 함
선택한 장소의 이름 문자열—✅ diary.location 컬럼 1개
좌표 · 도로명주소 · 카테고리 · place_id—❌ 저장 안 함
즉, 우리는 카카오가 공개하는 장소 이름 문자열만 일기 1건당 1개 저장합니다. 좌표나 카카오 내부 식별자(place_id), 카테고리 정보 등은 저장하지 않으며, 일기 자체가 그룹 비공개이므로 이 장소 정보 또한 그룹 외부로 노출되지 않습니다.

4. 이용 동선 — 첫 진입부터 카카오 로컬 호출까지

심사 담당자가 앱을 설치하지 않고도 전체 흐름을 따라갈 수 있도록, 첫 진입부터 카카오 로컬 API 호출 시점까지 8단계를 차례로 정리합니다. 4-6 단계가 본 신청의 핵심 호출 지점입니다.

STEP 1
앱 진입 — 스플래시
디그팟 브랜드 스플래시. 1~2초 후 로그인 또는 그룹 홈으로 자동 이동.
STEP 2
소셜 로그인
카카오 · 네이버 · 애플 소셜 로그인만 지원. 자체 ID/PW 가입 절차 없음. 약관 동의 1회 후 즉시 가입 완료.
STEP 3
그룹 생성 또는 초대 코드 입력
새 그룹을 만들거나, 친구가 공유해 준 6자리 초대 코드를 입력해 참여. 그룹은 비공개 — 외부 노출 없음.
STEP 4
그룹 홈 진입
하단 탭에서 “그림일기” 선택. 월별 캘린더에 일기 작성일이 표시됨.
STEP 5 ★
일기 작성 화면 — 메타 영역
날짜·기분·날씨를 고른 뒤 “장소 추가하기” 칩을 탭하면 검색 시트가 열립니다.
STEP 6 ★★ 핵심 호출 지점
장소 검색 — 카카오 로컬 API 호출
키워드를 입력하고 검색을 누르면 /v2/local/search/keyword.json 이 호출되어 결과 리스트가 표시됩니다. 사용자는 원하는 장소를 탭해 선택합니다.
STEP 7
일기 저장
선택한 장소의 이름 문자열만 diary.location 으로 자체 서버에 저장. 좌표/주소/place_id 는 저장하지 않음.
STEP 8
일기 상세 — 장소가 함께 표시
저장된 일기에는 사진·기분·날씨·장소 칩·본문이 함께 표시됩니다. 그룹 멤버 간에만 보임.

5. 카카오 로컬 API 호출 화면 (확대)

아래는 STEP 6 “장소 검색” 화면을 크게 확대한 것입니다. 이 화면에서 검색바에 키워드를 입력하고 검색 버튼을 누르는 순간 카카오 로컬 키워드 검색 API 가 1회 호출되며, 응답 결과가 하단 리스트에 표시됩니다. 사용자는 원하는 장소를 탭해 선택합니다.

그림일기 작성 → 장소 추가하기 → 카카오 로컬 검색 결과 리스트
호출 트리거: 사용자가 검색바에 텍스트를 입력하고 “검색” 버튼 또는 키보드 엔터를 누른 시점에만 호출. 타이핑 중 자동 호출(디바운스) 없음 → 불필요한 트래픽 발생 차단.

응답 처리 정책

  • 검색 결과(JSON)는 클라이언트 메모리에만 표시되며, 우리 서버로 전달하지 않습니다.
  • 사용자가 결과 중 하나를 선택한 시점에만, 그 장소의 place_name 문자열을 일기 저장 시 함께 서버로 보냅니다.
  • 좌표(x/y)·도로명/지번 주소·카테고리·place_id 등 부가 정보는 저장·재활용하지 않습니다.
  • 일기 자체가 그룹 비공개이므로 장소 이름 또한 그룹 외부에 노출되지 않습니다.

6. 예상 호출 트래픽

구간예상 MAU일일 호출량
현재 (베타)약 500명2,000 ~ 5,000 건
정식 출시 +3개월약 2,000명8,000 ~ 20,000 건
정식 출시 +6개월약 5,000명20,000 ~ 50,000 건

산정 근거: 1인당 주 2~5회 일기 작성 × 일기 1건당 평균 1~3회 키워드 검색. 피크 시간대(저녁 9~11시)에 일일 호출의 약 35% 가 집중되는 패턴.

7. 향후 확장 계획

  • 같은 장소로 작성된 일기 모아보기 — 일기 캘린더에서 동일 장소 그룹핑 (자체 구현, 추가 API 호출 없음).
  • 카카오맵 상세 미리보기 — 선택한 장소를 작은 지도로 시각화 (별도 카카오맵 JavaScript SDK 도입 시 추가 신청 예정).
  • 오프라인 캐싱 — 최근 검색 키워드에 한해 30분 클라이언트 캐싱, 동일 키워드 중복 호출 절감.

위 확장은 본 신청 범위에 포함되지 않으며, 도입 시 별도 변경 신청을 진행하겠습니다.
