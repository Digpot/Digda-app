# 신청 사유 및 활용 시나리오

> 카카오 디벨로퍼스 신청서의 "신청 사유 및 활용 시나리오" 입력란에 그대로 복붙해서 사용하세요.

---

## 1. 서비스 개요

- **서비스명**: 디그팟(DigPot) — 그룹 단위 다이어리·일정 공유 모바일 앱 (Android · iOS)
- **운영사**: DateDiary
- **출시 단계**: 베타 운영 중, 정식 출시 준비
- **타겟 사용자**: 가족·연인·친구 등 친밀한 소그룹

## 2. 카카오 로컬 API 활용 기능

### 그림일기 작성 시 "장소 태깅"
사용자가 일기를 작성할 때 그날 다녀온 카페·식당·관광지 등의 **장소 이름과 위치를 본문과 함께 저장**할 수 있도록 지원합니다. 이를 위해 작성 화면의 "장소 추가하기" 영역에서 카카오 로컬 키워드 검색 API(`/v2/local/search/keyword.json`)를 호출해 검색 결과 목록을 보여주고, 사용자가 선택한 장소의 `place_name`을 일기 레코드의 `location` 필드에 저장합니다.

### 호출 방식
- HTTP REST 호출 (Authorization 헤더: `KakaoAK <REST_API_KEY>`)
- 사용자가 검색바에 키워드를 입력하고 "검색"을 누를 때만 호출 (입력 디바운스 없이 명시적 트리거)
- 검색 결과는 클라이언트 메모리에만 표시, 별도 서버 저장·재활용 없음
- 일기 저장 시점에는 사용자가 *선택한 장소의 이름 문자열만* 자체 서버 DB에 저장 (좌표·주소 등은 저장하지 않음)

### 호출 예상 트래픽
- 사용자 1인당 일기 작성 빈도: 주 2~5회
- 일기 작성당 평균 검색 호출: 1~3회
- 베타 단계 MAU 약 500명 → 일일 검색 호출 약 2,000~5,000건
- 정식 출시 후 6개월 시점 MAU 5,000명 예상 → 일일 검색 호출 약 20,000~50,000건

## 3. 사용자 가치

장소를 함께 기록함으로써 다음 가치를 제공합니다.
- **기억의 풍부함**: 사진·텍스트·날짜·날씨·기분에 더해 *어디서* 라는 맥락을 한 번에 보존
- **그룹 공유의 의미**: 같은 그룹의 멤버들이 "거기 좋았지" 같은 공감대를 즉시 형성
- **회상 편의**: 추후 캘린더·검색에서 장소별로 추억을 되짚을 수 있는 기반 데이터

## 4. 개인정보·데이터 보호

- 카카오 로컬 API 응답에는 카카오가 공개하는 상호·주소·카테고리만 포함되며, 사용자의 개인정보는 카카오로 전송되지 않습니다 (검색 키워드만 전달).
- 사용자가 선택한 장소의 **이름 문자열만** 자체 서버 DB의 `diary.location` 컬럼에 저장합니다. 좌표/연락처/내부 식별자(id)는 저장하지 않습니다.
- 일기 자체가 비공개(그룹 멤버에게만 공개)이므로 장소 정보 또한 그룹 외부로 노출되지 않습니다.
- 카카오 REST API 키는 빌드 시점에 앱 바이너리에 포함되며, 별도 사용자 인증 없이 서비스 명의로 호출됩니다.

## 5. 호출 화면

별첨된 캡처 이미지 1장 참조. (그림일기 작성 화면에서 "장소 추가하기" 탭 → 검색 시트가 열리고 카카오 로컬 API 결과가 리스트로 표시되는 모습)

## 6. 향후 확장 계획

- 검색 결과에서 선택 시 카카오맵 상세 미리보기 임베드 (별도 카카오맵 JavaScript SDK 도입 검토)
- 일기 캘린더 화면에서 같은 장소로 작성된 일기들 모아보기
- 위 두 확장 모두 *현재 신청 범위에는 포함되지 않으며*, 도입 시 별도 신청 또는 변경 신청 예정.
